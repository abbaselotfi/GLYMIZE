## 2. Package/build contract

1. Own the native wrapper in `apps/desktop/` (workspace already includes `apps/*`), with `src-tauri/`, pinned compatible Tauri 2 CLI/crates and a committed Cargo lockfile. No new backend service, Redis, SQL plugin, Stronghold plugin or paid dependency in B. Those plugins belong to separately reviewed capabilities, not starter-template defaults.
2. Add an explicit build-time desktop reference profile, separate from `GLYMIZE_OFFLINE_BUNDLE_ENABLED`. Default web/RC behavior stays unchanged. The flag chooses presentation/build output only; it grants no clinical authority.
3. Use a dedicated build entry with an allowlisted environment and clean, repository-contained staging/export directories. Reject conflicting Pages/RC/public API/bypass settings; inspect Next `.env*` loading too, not only inherited shell variables. Never package a pre-existing `apps/web/out`. Isolate intermediate `.next`/export output or serialize with an explicit build lock; no concurrent web/desktop output overwrite.
4. Export with empty base path and root-relative local assets. Stage only the validated reference document, its required local JS/CSS/fonts/icons, P0 projection and a deterministic desktop manifest. Exclude `_worker.js`, `_headers`, `_redirects`, raw admin/catalog/market payloads, patient/admin/clinical route documents, source maps, secrets and source/build metadata beyond the manifest allowlist. Review shared chunks: absence of PHI documents is not proof that a shared chunk contains no admin code or embedded configuration.
5. Manifest records desktop profile/schema, app/source revision, asset paths/sizes/hashes and source freshness. Validate path traversal, case collisions on Windows, symlinks, missing/extra assets and partial export before packaging. Hashes detect corruption; they are not publisher signatures. Do not widen the existing P0 redistribution classification.
6. `frontendDist` points only to that reviewed stage; packaged startup opens the bundled reference entry. Development localhost is development-only. No production dev server, listening localhost service, CDN/font download, GitHub lookup, cloud login or updater check is required to start.
7. Preserve `/offline/` as the canonical renderer pathname. If Tauri's asset resolver needs an explicit `offline/index.html` entry, normalize only that exact packaged alias before route selection. Never let a fallback rewrite arbitrary patient/admin URLs into the public shell. Root navigation is a local reference landing or explicit unavailable view; remove the web-home link from this profile. Use document navigation where needed; do not invent RSC payloads from HTML. Prove nested load, refresh, query, fragment, back/forward and unknown paths in the actual packaged runtime. Unsupported routing must fail closed; do not silently add a Node sidecar.

## 3. Renderer/native security contract

- One local `main` window with native OS decorations. No custom application IPC handlers or privileged plugins in B; explicitly select only the reviewed capability configuration, initially no granted commands. Disable global Tauri API injection, remote capability URLs, asset filesystem scope, new windows, downloads, drag/drop imports, deep links and external navigation for this profile. Source citations remain visible as text; an OS-browser opener is a later scoped addition, not a generic shell command.
- Enforce the local navigation allowlist in native policy, including redirects and `target=_blank`; hidden buttons alone are not a boundary. No arbitrary file/SQL/HTTP/shell access and no webview creation command. No patient/API path becomes authorized because its HTML/JS was bundled.
- Future custom commands must be included in the application command permission manifest and separately enforce actor/practice/device/patient/grant/revision policy. An empty plugin permission list is insufficient if application handlers are later registered. Tauri documents implicit loading of capability files and default accessibility of registered app commands; pin explicit manifests rather than trusting scaffolding. [Capabilities](https://v2.tauri.app/security/capabilities/).
- Configure release CSP explicitly. Allow packaged scripts/styles/fonts/data reads only; deny remote frames, objects, forms, workers and connections. Determine exact local protocol origins from the pinned Windows build. Add IPC origins only if an accepted capability actually needs them. Preserve Tauri hash/nonce injection; do not disable CSP modification or add script `unsafe-eval`/blanket `unsafe-inline` to fix hydration. Next inline hydration and CSS must be verified against the generated policy, with violations failing acceptance. Any necessary narrow style exception needs recorded evidence. [CSP documentation](https://v2.tauri.app/security/csp/).
- CSP and navigation checks protect different surfaces; neither is patient authorization. Local asset corruption is a fail-closed unavailable state, not a network fallback. Renderer package integrity is not resistance to a local administrator replacing the executable; trusted signing/update recovery remains R30-08.
- No runtime auth initialization, catalog draft singleton, remote claim policy, PWA registration/update/reset, telemetry or external source fetching in the reference flow. No PHI input or persistent search. Existing minimal language/theme preferences may remain P1. Use a separate desktop application identity/WebView data directory; do not import browser localStorage, tokens or caches.
- Desktop installed/readiness copy comes from the validated packaged manifest plus successful local data loading, not `navigator.onLine`, SW headers or a network copy. Preserve reference-only/freshness/unknown-license warnings. If no valid data exists, display unavailable; never empty-success or clinical recommendations.

## 4. Windows packaging and costs

Initial acceptance target: Windows 11 x64; other architectures/Windows versions remain unverified until their own matrix passes. Keep standard non-admin application operation. Installer permissions and WebView prerequisite installation must be tested, not assumed.

Choose an NSIS candidate with WebView2 `offlineInstaller` for disconnected installation. A bootstrapper alone can still require Internet; `skip` fails when the runtime is absent. Fixed-runtime packaging is not the default because it transfers browser patch distribution to the application; revisit only with a patch/recovery plan. Record measured artifact size rather than promising a tiny package. [Windows installer options](https://v2.tauri.app/distribute/windows-installer/).

Read-only workstation probe: `cargo`, `rustc`, `cl` were not found on PATH, and the usual Visual Studio Installer `vswhere.exe` path was absent. This does not prove they are absent everywhere. No toolchain was installed in A. B can complete build/profile/configuration tests without a native build; C must provision or use an approved Windows builder and capture its versions. End users need neither Git, Node nor Rust. Private CI minutes, signing certificates/services and optional mirrors are not assumed free. No purchase, provider subscription or signing-key creation is part of this design.

Unsigned internal candidates must be labelled untrusted/test-only. Do not recommend disabling Windows security warnings. Signed installer/update provenance and independent distribution/offline update/rollback remain release gates under R30-08; a checksum alone cannot close them.
